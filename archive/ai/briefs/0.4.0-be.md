## M1 — foundation
1. **Merge `feat/0.3.3-delete-archive` into your branch.** Resolve the conflicts with currency item 1, which you already listed: accounts, transactions, split_flow, and `other_currency_count`. Migration 061 stays.
2. **Wallets** (→ FE-pages)
   - Per wallet: `available` (balance − saved), `saved`, and this month's `in` / `out`.
   - Credit card wallets get new fields `credit_limit`, `due_day` and an optional `statement_day`, plus `due_date_next` and `days_until_due`. Check `statement_date` in spec 03.
   - List summary: `total`, `cash_total` (non-credit), `card_debt`, `card_used_pct`, `saved_total`, `available_total`, and counts per type for the group headers.
3. **Debts** (→ FE-pages)
   - Per person: `days_outstanding` (age of the oldest open entry) and the current-cycle boundary (`cleared_at`, the last time the balance hit 0).
   - Entries split into the current cycle and earlier cycles.
   - List summary: `owed_to_me {amount, people}`, `i_owe {amount, people}`, `over_30_days_people`.
   - A generated **summary message** text for a person (the open entries + total, Thai, both directions).
4. **Saving goals** (→ FE-pages)
   - Per goal: `month_plan`, `month_saved`, `month_short`, `eta_date`, `status` (on_track / behind_n_months).
   - List summary: `saved_total` (all savings incl. unallocated), `month_short_total`, `unallocated`.
   - **Auto-saving lives on the goal** (and on unallocated): amount, day, source wallet or none → a 🐷 pending draft on the day.
   - Migrate the existing recurring ออม rules to goal auto-saving (data is disposable; a simple move is fine).
   - Saving entries with no wallet stay NULL (done on the 0.3.3 branch).
5. **Categories** (→ FE-core): per category this month `spent` and `count` (counts transactions, includes sub-categories).

## M2
6. **Contacts**: nothing new beyond the existing fields. Check that the archive / delete rules from 0.3.3 hold.
7. **Budgets detail** (→ FE-pages)
   - `available` (limit − used), `daily_allowance`, `projected_end`, `days_left`, `pace_pct`.
   - For each counted transaction, a `reason` (category / sub-category / tag / wallet / all-expenses).
   - A periods list (one row per period: used / limit), with a per-period limit override (PATCH).
8. **Events** (→ FE-pages)
   - Per event: `my_share`, `my_paid`, `my_receivable` (+) / `my_payable` (−), and `planned_amount` with remaining.
   - Per member: paid and receivable / payable.
   - List summary: active `my_share_total`, `paid_total`, `receivable_total`, counts active / unsettled / ended.
   - **Event tags**: every member may create / rename / recolour / delete (one shared set). Bills filter by event tag.
9. **Transactions list** (→ FE-pages): month summary (`income`, `expense`, `net`, `avg_daily_spend`) and a daily spend series for the month. Both follow the list's date filter.

## M3
10. **Pending** (→ FE-core). Logic only; the pending page UI is not redesigned in 0.4.0 (owner 2026-10-17), so build it all, the FE wires only what needs no visible change.
    - Summary: `count`, `expense_total`, `income_total`, counts per source (recurring / manual / other people / slip).
    - `needs_input` per draft (no amount / category / wallet) and its count. An amount-less เตือนจ่าย draft is valid and confirm is rejected until it has an amount.
    - A **bulk confirm** of the ready drafts, plus a per-draft confirm.
11. **Notifications** (→ FE-core)
    - Inbox summary: `needs_answer`, `unread`, `dismissed` counts. The dismissed filter and restore already exist on the 0.3.3 branch.
    - `project_invite`: include it in `AwaitsAnswer`; accept / reject at `/projects/link-requests/:id/accept|reject`.
    - Event-row deep links: point them at a route the app has (agree it with FE-core).
    - `recurring_ending`: actions ต่ออีก / ปล่อยให้จบ. `recurring_due`: link to pending.
    - Settings: drop the retired `split_paid` / `split_received`; expose recurring_due / recurring_ending as mutable. Move `auto_resolve_own_in_projects` out of notification settings into an event / profile setting (agree the shape with FE-core).
12. **App settings** (→ FE-core): `default_account_id` on /me (if not there already), and an **archived hub** endpoint (counts + lists of archived wallets / budgets / goals / events / contacts / recurring).

## M4 — recurring (→ FE-pages, recurring picker → FE-core)
