## 3. ลบกระเป๋า (ใหม่)

**API:** `DELETE /v1/accounts/:id` = **ลบจริง** (เดิมหมายถึงเก็บถาวร — breaking) · เจ้าของเท่านั้น · ปฏิเสธ `409 ACCOUNT_HAS_MEMBERS` ถ้ายังมีสมาชิก active คนอื่น (ต้องเอาออกก่อน)

**ขั้นตอน (DB tx เดียว, ระดับ service):**
1. lock กระเป๋า
2. ลบรายการระบบของกระเป๋า (ยอดเริ่มต้น / ปรับยอด) — มีไว้ขับยอดกระเป๋านี้อย่างเดียว
3. `UPDATE transactions SET account_id = NULL` — ทุกแถวที่เหลือ ทุกคนที่เขียน (รวมสมาชิกที่ออกไปแล้ว → ไปอยู่ในสมุดเขาแบบไม่ผูกกระเป๋า) **รวมขาโอนทั้งสองแบบ** (§5.2)
4. รายการประจำของกระเป๋า → `account_id = NULL` (สถานะไม่เปลี่ยน ยังสร้างรายการต่อแบบไม่ผูกกระเป๋า)
5. เป้าออมของกระเป๋า → `linked_account_id = NULL` (เก็บไว้ ดู §5.3)
6. `DELETE` กระเป๋า (account_members cascade)
- `user_notification_settings.default_account_id` → NULL (FK มีอยู่แล้ว) · ร่างใน pending ที่อ้างกระเป๋านี้ (JSON ไม่มี FK) → ตอนส่งจะได้ `last_error` ให้เลือกกระเป๋าใหม่

**ตัวอย่างก่อนลบ:** `GET /v1/accounts/:id/delete-preview` → `{transactions, transfers, system_rows_deleted, scheduled, saving_goals}` ให้แอปขึ้นข้อความเช่น "N รายการจะไม่ผูกกระเป๋า · รายการประจำ N · เป้าออม N จะไม่ผูกกระเป๋า · รายการระบบ N จะถูกลบ"

## 4. เก็บถาวรกระเป๋า — ไม่ถูกนับทุกที่ + ห้ามเขียน

**API:** `POST /v1/accounts/:id/archive` · `POST /v1/accounts/:id/restore` (ใหม่) · `PUT /accounts/:id` **ตัด `status` ออก** (เดิมข้ามกฎสมาชิก) · list `?status=active|archived|all` คงเดิม · สถานะ `closed` → `archived`

**ไม่ถูกนับ (จุดกลางจุดเดียว):** เพิ่มเงื่อนไขกระเป๋า `status <> 'archived'` ใน `shared.ReportScopePredicate` (แถวไม่มีกระเป๋ายังนับ) → ครอบ: สรุปรายการ (Summary / byCategory / byAccount / byDate) · งบ `ComputeSpent` · แดชบอร์ด (summary / หมวด / trend / top / recent)

**จุดที่แก้เพิ่ม:**
- รายการเงิน list + `totals`: ซ่อนแถวของกระเป๋าที่เก็บถาวรเป็นค่าเริ่มต้น · ยังเห็นเมื่อกรอง `account_id` = กระเป๋านั้น (หน้ารายละเอียดกระเป๋า) หรือ `include_archived=true`
- `accounts` GetByID / Summary อ่านได้ (หน้ารายละเอียด) แต่ไม่รวมในยอดรวม
- รายการประจำของกระเป๋าที่เก็บถาวร: ซ่อนจาก list / upcoming / DueScheduled · ไม่สร้างรายการ (status ไม่เปลี่ยน)
- เป้าออมของกระเป๋าที่เก็บถาวร: ซ่อน (derived) — §5.3

**ห้ามเขียน → `409 ACCOUNT_ARCHIVED`:** ประตูเขียนรายการ (`GetAccountBalanceTx`: สร้าง / แก้ / ย้ายเข้า / โอนเข้า-ออก) · GenerateNow + สร้าง/แก้รายการประจำ · quick create / claim โปรเจกต์ · ปิดหนี้เข้ากระเป๋านี้ · ส่งร่างใน pending

**แอป:** เปลี่ยน "เก็บเข้าคลัง" / "เก็บ" → **"เก็บถาวร"** · เพิ่มปุ่มลบพร้อม dialog จาก delete-preview · ปุ่มเก็บถาวรย้ายไปเรียก `POST /archive` · หน้ากระเป๋าที่เก็บถาวรมีอยู่แล้ว

## 5. ของที่ไม่ต้องผูกกระเป๋าอีกต่อไป

### 5.1 รายการประจำ
- **กระเป๋าไม่บังคับทุกที่** (ไม่ใช่แค่หลังลบกระเป๋า): `account_id` nullable · ไม่มีกระเป๋า = สร้างรายการแบบไม่ผูกกระเป๋า และไม่แตะยอด
- สร้าง/แก้: ถ้าใส่กระเป๋าต้องเป็นของเรา + active (ไม่ถูกเก็บถาวร)
- Upcoming / AccountSnapshots / DueScheduled: `LEFT JOIN accounts` · ข้ามเฉพาะที่กระเป๋าถูกเก็บถาวร
- **สถานะ:** `active` / `inactive` / `completed` / `archived` + ลบ
  - `paused`, `cancelled` เดิม → `inactive` · `completed` คงเดิม (ตั้งอัตโนมัติเมื่อ `remaining_installments` = 0) · แก้จำนวนงวดจน > 0 → กลับเป็น `active`
  - `completed` สั่ง activate / deactivate ไม่ได้ → `409 SCHEDULE_COMPLETED`
  - เก็บถาวรได้จากทุกสถานะ · คอลัมน์ใหม่ `status_before_archive` → กู้คืนกลับสถานะเดิม (ถ้าเดิม active แต่ตอนนี้กระเป๋าถูกเก็บถาวร → กลับเป็น inactive)
- **API:** `POST /:id/activate` · `/deactivate` (แทน `/pause` + `/cancel` ซึ่งเอาออก) · `/archive` · `/restore` · list ค่าเริ่มต้น = active + inactive + completed · `?status=archived` / `all`
- **แอป:** ตัวเลือกกระเป๋ามี "ไม่ผูกกระเป๋า" · sheet สถานะ: ใช้งาน / ไม่ใช้งาน / เก็บถาวร + ลบ · "ครบแล้ว" เป็น pill (ผู้ใช้เลือกเองไม่ได้) · ตัวกรอง "แสดงที่เก็บถาวร" · **แก้บั๊ก** รายการที่พักไว้หายหลังโหลดใหม่ (ค่าเริ่มต้นใหม่ของ list แก้ให้เอง)

### 5.2 ขาโอนที่ไม่ผูกกระเป๋า
- การโอนยังเป็น 2 แถวที่มี `transfer_group_id` เดียวกัน · แยก OUT/IN จากหมวดระบบ (Transfer Out / Transfer In) ไม่ใช่จากกระเป๋า → ลบกระเป๋าแค่ทำให้ขาของมัน `account_id = NULL` · อีกขายังเป็นการโอนเหมือนเดิม ยอดกระเป๋าที่เหลือไม่เปลี่ยน · รายงานไม่กระทบ (หมวดโอน `include_in_report = false`)
- ไม่มี DB CHECK ผูกการโอนกับกระเป๋า (กฎอยู่ใน API) — ไม่ต้อง migration
- **BE:** authz ของคู่โอน (`authorizePairMutation`) รับขาที่ไม่มีกระเป๋า (ใช้ผู้เขียนแทน) · เช็กกระเป๋าเดียวกัน / สกุลเงิน เฉพาะเมื่อมีกระเป๋าทั้งสองขา · ผ่อนกฎ `ErrMoveTransferNeedsToAccount` ให้เลือกกระเป๋าใหม่ทีละฝั่งได้ (`account_id` = ฝั่ง OUT, `transfer_to_account_id` = ฝั่ง IN) · ตรวจทุกจุดที่ขยับยอดว่าข้ามขาที่ไม่มีกระเป๋า
- **owner ตัดสิน:** สร้างการโอนแบบไม่มีกระเป๋าฝั่งใดฝั่งหนึ่ง **ไม่ได้** · แก้ไข: เลือกกระเป๋าให้ฝั่งที่ว่างได้ (re-file) แต่ล้างฝั่งที่มีออก **ไม่ได้** → ขาไม่ผูกกระเป๋ามาจากการลบกระเป๋าเท่านั้น
- **แอป:** หน้ารายละเอียดแสดง "จาก: ไม่ผูกกระเป๋า" / "ไป: ไม่ผูกกระเป๋า" · แถวในรายการแสดงการโอนที่ขาดฝั่ง · แก้ไขมีตัวเลือกกระเป๋าให้ฝั่งที่ว่าง

### 5.3 เป้าออม
- **สร้าง: ต้องมีกระเป๋า** (owner ตัดสิน) · `linked_account_id` nullable ได้จากการลบกระเป๋าเท่านั้น (FK `ON DELETE SET NULL`) · `allocation_pct` คงค่าไว้ ใช้ต่อเมื่อเลือกกระเป๋าใหม่
- **ไม่ผูกกระเป๋า:** `current_amount` 0 · `progress_pct` 0 · `remaining` = เป้า · `is_completed` false · `linked_account` = null (เดิมเป็น object เสมอ — แอปต้องรองรับ null) · **ซ่อนจาก tile แดชบอร์ด** (owner ตัดสิน) · ไม่นับใน allocation
- **เลือกกระเป๋าใหม่ (re-link):** `linked_account_id` แก้ผ่าน PUT ได้ (เดิม "ลบแล้วสร้างใหม่") · ต้องเป็นกระเป๋าของเรา active · เช็กพื้นที่ (รวม ≤ 100%) ใหม่
- **กระเป๋าถูกเก็บถาวร → ซ่อน (derived):** ไม่อยู่ใน list ค่าเริ่มต้น / tile / allocation / ไม่คำนวณความคืบหน้า · `?status=archived` คืนทั้งเป้าที่เก็บเองและเป้าที่กระเป๋าถูกเก็บ พร้อม `archived_reason: "goal" | "wallet"` · กู้คืนกระเป๋า → กลับมาเอง · ระหว่างนั้น แก้ / เก็บ / กู้คืนเป้า → `409 ACCOUNT_ARCHIVED` (ลบได้)
- **แอป:** การ์ด/หน้าเป้าที่ไม่ผูกกระเป๋า: "ไม่ผูกกระเป๋า" + 0% + ปุ่ม "เลือกกระเป๋า" · หน้าดูที่เก็บถาวรแสดงเหตุผล ("กระเป๋าถูกเก็บถาวร")

## 6. ของอื่นที่เปลี่ยน

### 6.1 ผู้ติดต่อ (เก็บถาวรมีอยู่แล้ว)
- สร้างหนี้ / หารบิล กับผู้ติดต่อที่เก็บถาวร → `409 CONTACT_ARCHIVED`
- หารกับคนที่เชื่อมบัญชี: ฝั่งเขาเลือกผู้ติดต่อ **active ก่อน** (แก้ `LIMIT 1` ที่อาจได้ตัวที่เก็บถาวร)
- ไม่ bump `last_used_at` ของผู้ติดต่อที่เก็บถาวร
- **หนี้ของผู้ติดต่อที่เก็บถาวร ยังนับในยอดหนี้และ tile แดชบอร์ด** (เงินจริง — owner ตกลง)
- แอป: มีตัวกรอง + กู้คืนอยู่แล้ว

### 6.2 แจ้งเตือน — "ซ่อน" = เก็บถาวร
- BE: list ซ่อนรายการที่ `dismissed_at` ไม่ว่างเป็นค่าเริ่มต้น · `?dismissed=true` = หน้าที่ซ่อน · ใหม่ `POST /v1/notifications/:id/restore` (ล้าง `dismissed_at`) · จำนวนยังไม่อ่านไม่นับที่ซ่อน · `DELETE` มีอยู่แล้ว
- แอป: หน้า/แท็บ "ที่ซ่อนไว้" + กู้คืน + ลบ

### 6.3 โปรเจกต์ — ลบจริงได้แม้มีรายการ
- DB tx เดียว: ล้างลิงก์สำเนาส่วนตัวของ**ทุกคน** (`UPDATE transactions SET project_id = NULL, source_project_transaction_id = NULL` สำหรับแถวที่ชี้รายการในโปรเจกต์นี้) → สำเนายังอยู่เป็นรายการส่วนตัวธรรมดา · หนี้ `project_id` → NULL (FK ทำให้แล้ว) · `DELETE` โปรเจกต์ (สมาชิก / รายการ / งบระดับโปรเจกต์ cascade)
- เอา `409 ErrProjectHasTxs` ออก · เจ้าของเท่านั้น · ไม่ส่งแจ้งเตือนหาสมาชิก (กฎ ledger: ไม่แจ้งเมื่อลบ)
- สถานะโปรเจกต์ (active / completed / cancelled / archived + กฎล็อก) คงเดิม
- แอป: ข้อความยืนยัน "ลบโปรเจกต์และรายการทั้งหมดในโปรเจกต์ · รายการในสมุดส่วนตัวยังอยู่"

### 6.4 รายการในโปรเจกต์ — บั๊ก (ทำก่อน)
- ตอนนี้ลบรายการที่มีสำเนาส่วนตัวจะ error: FK `SET NULL` ล้าง `source_project_transaction_id` แต่ `project_id` ยังอยู่ → ผิด CHECK `transactions_project_id_implies_source` (mig 25)
- แก้ (service, ก่อนลบ): `UPDATE transactions SET project_id = NULL, source_project_transaction_id = NULL WHERE source_project_transaction_id IN (แถวนี้ + split ลูก)` → สำเนาอยู่ต่อแบบไม่ผูกโปรเจกต์ · ไม่ต้อง migration

### 6.5 หมวด
- ลบคอลัมน์ `categories.status` (ตายแล้วตั้งแต่ mig 43) + เงื่อนไข `status = 'active'` ที่ค้าง (List, CountChildren, Reorder, personal_copy) + comment เก่าที่ยังพูดถึงการเก็บถาวร · พฤติกรรมลบเหมือนเดิม

### 6.6 งบ, เป้าออม (แอปอย่างเดียว)
- ตัวกรอง "แสดงที่เก็บถาวร" ในหน้ารายการทั้งสอง + ปุ่มกู้คืน (repo/cubit มีแล้วแต่ไม่มีใครเรียก) · กู้คืนอาจล้มได้: เป้าออม = พื้นที่เต็ม · งบ = ซ้ำกับงบที่ใช้งานอยู่

## 7. Migration `000053_states_delete_archive` (ไฟล์เดียว)

- `accounts`: `closed` → `archived` · CHECK (`active`, `archived`)
- `scheduled_transactions`: `account_id` DROP NOT NULL + FK `ON DELETE SET NULL` · `paused` / `cancelled` → `inactive` · CHECK (`active`, `inactive`, `completed`, `archived`) · + `status_before_archive VARCHAR(20) NULL`
- `saving_goals`: `linked_account_id` DROP NOT NULL + FK `ON DELETE SET NULL`
- `categories`: DROP COLUMN `status`
- `transactions.account_id` FK **ไม่เปลี่ยน** — service ล้างแถวก่อนลบกระเป๋า FK ไว้กันการลบหลุด
