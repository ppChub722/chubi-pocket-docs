## Rules used
- **Keep** a test only if it guards:
  - (a) logic where a bug means wrong money or wrong data: balances, debt / split / paid_by math, recurrence, budget and goal math, sync / offline, parsing, request bodies sent to the API, amount and date formatting
  - (b) the contract with the BE (API spec ratchet, page_flows)
  - (c) one smoke per page: it opens, and its main action saves with the right body
  - (d) a real past bug
- **Delete:**
  - looks: positions, sizes, colours, geometry, findsNWidgets counts, wording, which chip or tab shows
  - hub / demo tests and source ratchets (layering, raw widgets, feature visuals, page refresh, hub coverage)
  - UI state that doesn't change what gets saved
  - duplicates of a page test
- **Merge:** several cases of one rule → one table-driven test.

## How to cut (when the owner says go)
- One folder at a time: delete files, then trim / merge, then run THAT folder only (CLAUDE.md output rules).
- The tests that are red today (backlog "0.4.0-4 carried over") mostly sit in files this cut deletes or trims. Fix only what is kept.
- Afterwards: CLAUDE.md and the role skills say a new piece needs a test only when it guards (a)–(d) above.
