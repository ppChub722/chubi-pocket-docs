# 0.4.0 plan — the UI round (Lead, 2026-10-17)

**Goal:** every page's UI matches the approved design reference **"Chubi Page Reference"** — https://claude.ai/artifact/EJq2vwbaKkYmMu27ZtZPZ7 (sections 0–12; read the section of each page you touch). Version **0.4.0** = "every page's UI is done". Rules are in `ai/decisions.md` (UI section, "Design reference", "Edit mode layout", notes, tags, currency, contacts vs debts).

## Ground rules for the UI (owner 2026-10-17)
1. **The artifact is the LAYOUT reference only**: what sits where, the section order, what goes on the card, what hides in edit mode. Follow its arrangement.
2. **Every look comes from the app's hub / kit** (colours, fonts, spacing, sizes, frames, chips, cards, inputs). No page builds its own look, not even once.
3. **The artifact is an HTML mockup with its own fonts, colours and spacing.** Where it doesn't match the kit, don't copy it. Look at how the existing app pages arrange the same kind of thing (spacing, sizes, frames) and reuse that. Then check the artifact again to make sure the result still fits its layout.
4. **A missing piece** (hero rows A–G, end zone, page indicator, people strip…) is built by FE-core IN THE KIT, extending the existing patterns (that design is approved). It goes into the hub, then the pages use it.
6. **API rules (owner 2026-10-17, repeated):**
   - **Few endpoints.** Reuse / extend the existing endpoint first (add fields to its answer); create a new endpoint only when no existing one fits.
   - **Page-ready answers.** Whatever a page shows, the BE puts in the answer, ready to display (names, totals, states, captions). The FE never combines several calls or derives numbers.
   - **One page open = one call** (most pages). Sub-parts of a page (summary card, message, tabs' first page) come in that same answer, not separate calls. One button = one call.
7. **Refresh on show (owner 2026-10-17):** every page re-runs its ONE page call each time it becomes visible again: switching shell tabs (4 bottom + 3 top) and coming back (pop) from a page opened on top. Silent: keep the current data on screen, reload in the background, swap when it arrives (no skeleton, no flicker; skeleton = first load only). A failed refresh keeps the data and shows the usual offline / error state. **Pull-to-refresh on every page and every tab.** Both are built ONCE in the page templates / shell (FE-core), so pages get them for free; a ratchet test fails any page template without them.
5. Every part of the reference is approved (2026-10-17) and in 0.4.0 scope, unless it is marked 0.4 / later.

## Running without the owner (owner 2026-10-17)
- Work runs straight through to the end of M5. Lead merges each milestone and tells the others to rebase.
- **Non-breaking choices you hit along the way: decide them yourself (or with the peer it touches) and keep going.** Write each one in your inbox report under "Decisions taken" (one line: what · why · how to undo). Lead confirms or overrides them and collects them for the owner.
- Anything that breaks something (data loss, a contract another session relies on, a rule in `ai/decisions.md`, a removed feature): stop that item, ask Lead, and continue with the next item meanwhile.
- New kit pieces: build and use them right away; the owner reviews them all at the end (no per-piece hub review this round).
- No local build, no tag, no push: the owner reviews tomorrow.

**Out of scope:** the **pending page UI** (reference section 10 layout; its logic / BE work IS in scope; owner 2026-10-17), push notifications and the planned notification types (0.4 list in the reference), family-plan sharing, the LLM text input (0.3.2; the 💬 button stays hidden), CSV export, deploys (local only).

## Working setup
- **Each session works in its own git worktree on its own branch**: `feat/0.4.0-be`, `feat/0.4.0-fe-core`, `feat/0.4.0-fe-pages` (from current main: be `1b5dfe0`, app `4c6ce78`). Commit locally, small and often. **Never push, tag, or merge to main.** Lead merges into main after each milestone and tells the others to rebase.
- **Shared files** (`lib/l10n/app_*.arb`, `app_router.dart`, `ui.dart`): FE-core is the owner. FE-pages may add arb keys in a block marked `// fe-pages` and new routes, but rebases on FE-core first and keeps those commits small.
- **API first**: BE writes the OpenAPI shape for each item, sends it to the FE that needs it, then implements. FE may build against the agreed shape before it lands.
- **Tests**: run only the tests for what you changed. Lead runs the full `flutter analyze` / `flutter test` / `go vet` / `go test` at each merge.
- **Reports**: `ai/inbox/<role>.md` (newest on top) + a one-line DONE ping to Lead. Questions → Lead. Peers may talk directly about shapes and kit pieces.
- English everywhere except Thai UI strings. No AI attribution in commits. Don't run the app for the owner.
