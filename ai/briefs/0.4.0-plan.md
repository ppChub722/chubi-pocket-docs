## Working setup
- **Each session works in its own git worktree on its own branch**: `feat/0.4.0-be`, `feat/0.4.0-fe-core`, `feat/0.4.0-fe-pages` (from current main: be `1b5dfe0`, app `4c6ce78`). Commit locally, small and often. **Never push, tag, or merge to main.** Lead merges into main after each milestone and tells the others to rebase.
- **Shared files** (`lib/l10n/app_*.arb`, `app_router.dart`, `ui.dart`): FE-core is the owner. FE-pages may add arb keys in a block marked `// fe-pages` and new routes, but rebases on FE-core first and keeps those commits small.
- **API first**: BE writes the OpenAPI shape for each item, sends it to the FE that needs it, then implements. FE may build against the agreed shape before it lands.
- **Tests**: run only the tests for what you changed. Lead runs the full `flutter analyze` / `flutter test` / `go vet` / `go test` at each merge.
- **Reports**: `ai/inbox/<role>.md` (newest on top) + a one-line DONE ping to Lead. Questions → Lead. Peers may talk directly about shapes and kit pieces.
- English everywhere except Thai UI strings. No AI attribution in commits. Don't run the app for the owner.
