## 1. Shared bills (agreed)
- An **event bill** and a **split bill with linked contacts** are the same thing: a shared bill. Every member holds their own **copy** in their book, so a copy can keep old values while that member's auto sync is off ("ไม่ตรง").
- **One form for everyone:** A, me and B open the same bill form (total, payer, every share; my share marked).
- **Create** from the normal quick create (add to an event / create one, or split with people). **Once created, "edit" on that tx always opens the bill form** (event bill sheet / split bill form), whatever the auto-sync switch.
- **Who edits:** event bills by the event's rights; split bills by every member.
- **Reaching the others:** a saved bill reaches each other member by THAT member's auto sync: on → their copy changes at once; off → a notification asks "อัปเดตตาม"; "no" → their copy shows "ไม่ตรง", still connected.
- **Event completed** → "edit" opens the tx's own edit; no more sync. **Disconnect** → a plain tx, edited freely.
- **Not synced:** category, wallet, tags (each member picks; they arrive as "เลือกหมวด" / "เลือก tag"). When someone else paid, my wallet slot shows "จ่ายโดย A" (+ the tick "คืน A แล้ว" brings the wallet picker back, no debt), and the debt "ฉันติด A ฿…" shows in my person book.
- **Notes:** `note` = the shared note (synced); new `private_note` = mine only, never synced; only on shared records.
- **Person rows (line 2):** [จ่าย] [คืนแล้ว] in both forms; "คืนแล้ว" = the debt + an immediate repayment (as quick create split does today). Both forms get a debt summary card ("B ติดฉัน +300 · C คืนแล้ว") before saving.
- **Auto sync:** two switches, events and debts / split bills with a linked contact; each is the member's own; one value in the DB, shown and changed from several places (notification settings, profile settings, the event page, the person page). Auto sync and muting a notification are separate settings.
- Moves the 0.4.1-1 known gap here: in the tx edit, switching "ผูกกับ" off อีเวนต์ or moving event A → B changes the bill; with the bill form this happens there.

## 2. Events revamp (from the concept, agreed)
- **Lump** ("claim ก้อน"): ONE debt "ฉันติด X" connected to many "จ่ายโดย X" txs; based on the real pairs; remembers its bills; any time, active or completed.
- **Claim = connect from the other end:** from my debt / tx form → pick an event → pick a bill or create one (a debt-type bill from the debt form).
- **Debt-type bill:** today's `payback` widened (pay back, lending during the event); claimable like any bill.
- **Completed = locked for good:** owner-only, after a confirm, can't be undone; no more add / edit; every book unsyncs at once; claiming after it = a one-time copy.
- **Settle:** real pairs while active (0.4.1-1 did this); "จ่ายน้อยครั้งสุด" only after completion, with "ลงในสมุดฉัน" = a one-time set (a plain tx for the money that moves + person-book entries without a tx).
- **Deleting a bill:** auto sync on → my connected tx / debts go too; off → a notification asks.

## 3. Recurring "หนี้" kind (agreed)
A new kind tied to a person; chips จดหนี้ | จ่ายหนี้ + the arrow; slots filled by person-book entries; จ่ายหนี้: amount = min(rule, balance), one waiting at a time, pauses at balance 0 and runs again on a new debt.

## 4. Every user setting on the server
Theme, theme mode, font, language, last wallet, with a local cache for boot (hide amounts: removed for now, owner 2026-10-27; every page's settings: survey running). **Owner 2026-10-27: this includes the sync settings** — the two auto-sync switches (S4) and the notification mute settings live on the server only, one value each, read the same from every page; nothing sync-related stays device-only. (Survey: last wallet is already worked out on the server; the BE takes `theme` / `language` as any string, and every stored value is a registration default no app ever sent.)
