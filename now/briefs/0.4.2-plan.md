# 0.4.2 plan — LLM: free text → pending draft, from the app and from Telegram (DRAFT, not briefed)

_Lead (next build), 2026-10-28. Owner: "0.4.2 llm เลย" + "telegram chat เชื่อม go เรา" + "มีสองทาง: chubi-app / telegram-chat". Builds on the 0.4.1-2 tree once its Lead commits. Nothing here is decided until the owner answers the questions at the end._

## What exists (survey 2026-10-28)
- **No LLM code.** No `anthropic-sdk-go` in go.mod; no LLM config keys.
- `POST /pending-transactions/parse-text` = stub (`imports/handler.go:239`, `{text}` 1–500 chars → `{"pending":[]}`); only the /dev/imports lab calls it.
- Pending: table (046 / 060) has `source` (manual, ocr, chat, …), `kind` (create | settle_debt | update_tx | saving), `draft` JSONB, `source_ref`. **Create always writes `source=manual`** (`pending/service.go:85`): a chat / ocr row can't be saved today. A draft can become a tx (incl. transfer, splits, paid_by), an event bill (single payer), a saving entry, a debt settle, a tx edit. **Not:** multi-payer bill, person-book entry, recurring rule, goal, budget, wallet, contact, category, tag.
- App: pending page `ChatDial` FAB has no `onSend`; "import slip" chip is a no-op.
- Slip scan (OCR + K PLUS rules) works but its drafts are never saved to pending; dedupe is in memory.
- Prod secrets: `/srv/chubi/.env` (+ the key list in `docker-compose.deploy.yml`). Never in the APK.

## Shape
```
chubi-app chat box ──┐
                     ├─▶ BE parse core: text + user context → LLM → drafts → pending rows (source chat / telegram)
Telegram bot ────────┘        one prompt, one JSON schema, one set of rules
     ▲                                   │
     └── reply: drafts + [✓ บันทึก] [✎ แก้ในแอป] [✗ ทิ้ง] ◀──┘   the app's pending page lists the same rows
```
- **Ledger, not sync:** a message never books anything by itself; it makes pending drafts. Confirm = one tap (Telegram button or the app).
- Everything in the one Go service (decision 2026-10-09).

## Work items
### Core — BE (C)
- **C1 LLM client** `internal/platform/llm`: anthropic-sdk-go; config `ANTHROPIC_API_KEY`, `LLM_MODEL` (default `claude-opus-5-5`), `LLM_EFFORT` (default `low`), timeout; structured output via `output_config.format` (never forced `tool_choice`: 400 on Opus 5.5); `stop_reason` refusal / max_tokens handled; server-side refusal fallback on.
- **C2 Usage log + cap:** table `llm_calls` (user, channel, model, tokens in / out / cache, ms, status, pending ids); per-user daily cap (default 100 calls) → 429 `LLM_LIMIT`. Spend cap also set in the Anthropic Console (owner).
- **C3 Parse core:** input = text + today (Asia/Bangkok) + the user's wallets / categories / tags / contacts / open events as enums (stable system prompt cached; user context after it). Output = a list of drafts (one message may hold several: "ข้าว 60 กาแฟ 45"), each with `missing` fields and a confidence; unknown → no guess. Thai + English.
- **C4 Save to pending:** a server-side create path for `source = chat | telegram` with `source_ref` (`channel`, original text, message id for dedupe). `parse-text` becomes real: `{text}` → saves + returns the rows (page-ready, `resolved` included).
- **C5 Eval set:** ~40 real-style Thai messages with expected drafts, run on demand (not in CI: costs money). Used to pick model / effort.

### Telegram — BE (T)
- **T1 Bot + webhook:** `POST /telegram/webhook` (public, checks `X-Telegram-Bot-Api-Secret-Token`); secrets `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`. Local dev uses long polling (`TELEGRAM_MODE=poll`), no public URL needed. Private chats only.
- **T2 Linking:** app → `POST /telegram/link` → one-time code (10 min) + `t.me/<bot>?start=<code>`; bot `/start <code>` binds chat ↔ user. Table `telegram_links` (user unique, chat_id, username, linked_at). Unlink from the app or `/unlink` in the chat. An unlinked chat gets "เชื่อมบัญชีจากแอปก่อน".
- **T3 Message → drafts → reply** with inline buttons; callback → submit / discard the pending row (same service calls as the app); the reply message is edited to show the result (บันทึกแล้ว / ทิ้งแล้ว / ยังขาด: กระเป๋า). Dedupe by `update_id`.
- **T4 (optional) slip photo** in the chat → existing scan-slip → pending (`source ocr`).

### App (A)
- **A1 Chat box** on the pending page: `ChatDial.onSend` → `parse-text` → the new rows appear in the list (existing draft cards) + one reply line; errors / limit / offline handled.
- **A2 Telegram link** in the central settings page (new row "เชื่อม Telegram": status, link button → opens the t.me link, unlink).
- **A3 Source on draft cards:** chip แชต / Telegram / สลิป + the original text under the card.
- Kit first: new widgets in ui.dart + /dev/widgets.

### Every module (M) — second half
- Envelope for a draft: `{module, action, payload}` where payload = that module's own create body (validation reused). Pending `kind` grows: `debt_entry`, `bill` (multi-payer), `recurring`, `goal`, `budget`, `contact`… (Lead proposal; order by how often the owner types them).
- The pending card per kind (app) and the Telegram reply per kind.
