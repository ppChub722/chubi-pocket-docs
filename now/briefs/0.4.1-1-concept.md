# 0.4.1-1 "linked = synced" — concept (in discussion)

Owner + AI-1, 2026-10-26. **Concept only, still being discussed: no code until the owner says go.** Agreed points are marked **Agreed**; the rest are proposals waiting for the owner.

## Words
- **connect** = two records know about each other (where one came from). Their values may differ.
- **sync** = the values are always the same: updated together, or one side reads the other's values.
- Rule of thumb: **one owner and the same fact → one truth** (connect + always sync, built by reading from the source, not by copying). **Different books (an event, another user) → connect + optional sync** (auto, or a notification that asks), built by copying + a drift check (`in_sync` exists today).

## 1. tx ⇄ recurring — Agreed: the tx FILLS the occurrence (not a sync)
- An occurrence is a **slot** in the rule's schedule; a tx fills it. Confirmed = filled with a tx. There is nothing to sync: the slot row keeps only `rule_id | slot | transaction_id` (or skipped / paid-without-tx) and reads every value from the tx.
  ```
  rule ค่าเน็ต 599 / month
   ├─ Jan ← [tx ค่าเน็ต 599]   filled (= that tx)
   ├─ Feb ← [skipped]
   ├─ Mar ← [paid without tx, ฿599]
   └─ Apr ← empty → shown as the rule's plan (due / upcoming)
  ```
- Confirm = create the tx and store its id in the slot (one DB transaction: the only write to both tables). Linking an existing tx = filling the slot with it.
- Edit the tx anywhere = one write to `transactions`; the slot just points at it. Today's code copies the tx values into the item `draft` on `also_update_link`: that copy goes.
- **`draft` is written only twice:** (1) the user adjusts an empty slot ahead (e.g. next month's promo at 100); (2) the filled tx is deleted (its last values are kept). While a tx fills the slot, `draft` is left alone and unused.
- An empty slot's amount = `draft` if any, else the rule.
- **Delete the tx → the slot becomes skipped automatically**, in the same DB transaction: `archived = true`, `draft` = the tx's last values (amount, wallet, category, tags, description, note), `date` = the tx date, `edited = true` (a later rule change won't overwrite it), `transaction_id` = NULL. A skipped slot shows no amount and counts nowhere.
- **Un-skip → due again with the last known values** (owner 2026-10-26). Example: rule 500 → adjusted ahead to 100 → confirmed (tx 100) → tx edited to 120 → tx deleted (skipped) → un-skipped → "รอจ่าย ฿120" (not 100, the stale plan; not 500, the rule). A slot never adjusted and never filled → the rule (500).
- A skipped slot can be filled straight away (confirm, link an existing tx, paid without a tx); no need to un-skip first. From the tx side: link to a recurring rule → pick the slot (skipped ones included). Check in planning whether today's link allows a skipped slot.
- **Paid without a tx needs an amount** (owner 2026-10-26; "แม่จ่ายให้" too): the only case where the slot row stores its own amount. The bulk "จ่ายแล้วที่เลือก" from 0.4.1-0 uses each slot's planned amount; a slot with no amount is left out ("needs amount"), like confirm.
- Disconnect = take the tx out of the slot: the tx stays as a plain tx, the slot is empty (due) again.
- Editing the rule changes only empty slots, never filled ones.
- Writes to the slot only: skip, disconnect, delete the tx (→ skipped), paid without a tx.
- Same for every kind: a saving slot is filled by a saving entry, a debt slot by a person-book entry.

### Overdue limit (all recurring) — Agreed
- At most **3 overdue occurrences waiting** per rule, whatever the frequency (days, months, years).
- When a 4th would come due, the rule turns **inactive** and stops making occurrences until the user deals with it.
- Proposed details (owner to confirm):
  - inactive = the existing pause with a reason ("ค้าง 3 งวด"), so there is one resume button; it shows in ต้องจัดการ;
  - on resume, it **continues from the slot where it stopped** (rent stopped at Apr → Apr, then May if already past), still at most 3 waiting, so nothing really paid is lost silently (corrected after the rent example: "next slot from today" would drop April);
  - the 3 waiting ones show as ONE row per rule with "บันทึกทั้งหมด | ข้ามทั้งหมด | เลือกเอง" (bulk API from 0.4.1-0);
  - auto-create rules: catch up at most 3 slots, then inactive as well.

## 2. tx ⇄ debt — Agreed
- A debt and its tx are **always connected and always synced** (equal amounts).
- A debt with no tx yet (a plain "จดหนี้") can connect by **creating a new tx** or by **connecting an existing tx**.
- **Disconnect depends on where the tx came from:**
  - tx created from the debt (จดหนี้ + ทำรายการเงิน, จ่ายหนี้ / รับคืน, แบ่ง, จ่ายแทน / รับแทน) = **debt tx**: can't disconnect. To get rid of it, delete the tx (the debt becomes a plain note again).
  - an existing tx connected later: can disconnect; the tx goes back to a plain tx, the debt to a plain note.
- Connecting an existing tx: the debt takes the tx's amount. A tx that is only partly the debt (1,000 sent, 500 of it a loan) is not a connect: use แบ่ง / partial จ่ายแทน.
- Synced fields = amount + date (the debt keeps its generated description).
- Only a plain tx in the matching direction can be connected, and a tx connects to one thing only (not to a recurring occurrence at the same time).
- A debt tx's debt (แบ่ง / จ่ายแทน) tapped "edit" on the debt page opens the edit of the same tx (no "can't edit").
- Gaps in the code today: the soft link ("บันทึกในรายการ", 076) has no sync; แบ่ง debts don't follow the tx date, a tx can drop below its split sum, deleting a แบ่ง tx leaves its debts behind (all three inferred from the code, not run).

## Debts: every case — Agreed (owner 2026-10-26)
- **Two books:** the wallet book (tx = money in / out of a wallet) and the person book (debts = who owes whom; a person's balance = all debts − all repayments).
- Every case answers two questions: **whose cost is it** and **whose money paid**.

| # | Case | Example | My wallet | My expense (budgets, reports) | Debt |
|---|---|---|---|---|---|
| 1 | I buy, I pay | food for me | −300 | 300 | – |
| 2 | someone paid for me ("จ่ายโดย X") | partner paid because I forgot my money; I borrowed from my brother to pay the shop | – | 300 | I owe X 300 |
| 3 | I pay, someone else bears it (แบ่ง) | brother says he covers mum's food | −300 | 0 | X owes me 300 |
| 3b | I pay, we share (แบ่ง) | 150 / 150 with a friend | −300 | 150 | X owes me 150 |
| 4 | lend | cash to B | −300, or no wallet | not counted | B owes me 300 |
| 5 | borrow | from my brother into my wallet | +300, or no wallet | not counted | I owe him 300 |
| 6 | pay back / get paid back | pay my partner next week | ±300, or no wallet (= paid outside the app) | not counted | the person's balance −300 |

- "Borrowed from my brother to pay" can also be recorded as 5 then 1 (cash in, then the purchase); the result is the same as 2.
- 6 is tied to the PERSON, never to a debt row; the tx of case 2 is never touched again.
- **Every person-book entry (lend, borrow, pay back, get paid back) works the same way:** a tx is optional; with a tx it is connected + always synced. Example: pay my brother back 300 without a tx → person book only (balance −300, wallet unchanged); with a tx → person book + a repayment tx (balance −300, wallet −300).
  - Counting: the person balance counts every entry, tx or not; a wallet changes only through a tx.
  - **"จ่ายแล้ว" stays a plain label** the user sets; it changes nothing (no FIFO, no "ไม่นับ" status).
  - Code change: repayments are stored as txs only today (`repay_contact_id`); a repayment without a tx needs a person-book row of kind "repayment", with the tx optional like a debt's.
- "No wallet" in 4–6 = the "ไม่มี" choice below: a debt only, no tx. "จ่ายหนี้" without a tx is how "paid outside the app" is recorded (no "ไม่นับ" status, no extra mark needed).
- A tx connected to a debt keeps its wallet (the money really moved); a tx of 4–6 is not an expense / income.
- **Quick create, debt mode — one form, four kinds (owner 2026-10-26):**
  ```
  [จดหนี้ | จ่ายหนี้] + the direction arrow → ให้ยืม | ยืม | จ่ายคืน | รับคืน
  [ฉัน or wallet] ⇄ [กับใคร]
  amount | description | date
  หลังบันทึก: … (the summary row as today)
  บันทึกในรายการ [on / off]   (was "ทำรายการเงิน"; now on every kind, pay back included)
     off → the "ฉัน" card (person book only)
     on  → the wallet card; tapping it: a wallet | ไม่ระบุกระเป๋า | ผูกกับรายการที่มีอยู่… + tags
  note
  กำหนดจ่าย (ให้ยืม / ยืม) | ปิดหนี้ = the "จ่ายแล้ว" label (จ่ายคืน / รับคืน)
  ```
  - The kinds stay separate (the user says what they mean); they differ in category, default amount (pay back = the open balance) and the extra row.
  - Connecting an existing tx: the card shows that tx ("โอนเงิน ฿300 | KBank"); amount and date come from it. **The tx always becomes the debt kind's category** (no question asked; the old category is kept for a disconnect). Cases: a transfer recorded first and known to be a loan later; money in recorded as income, really a loan; a transfer back recorded as an expense; "ซื้อข้าวให้แม่ ฿300", then my brother says he'll cover it → record "ให้กู้ยืม พี่ 300" and connect the tx instead of deleting it (my expense becomes 0, which is right: it isn't my cost). Same numbers as delete + new debt, or แบ่ง (him 300 | me 0). Only part of it covered (150 of 300) → amounts differ, so not a connect: **edit that tx into a split bill** (ผูกกับ → แบ่ง: him 150 | me 150; it stays food, my expense 150, he owes me 150). No shortcut or hint in the debt form (owner 2026-10-26): connecting just sets the debt to the tx's amount; splitting is the user's own choice in the tx (him 300 | me 0 works too).
  - **Description:** typed freely on every kind, optional; empty = stored empty and shown as the category name (no generated "ให้ ลี ยืม" text any more; old rows keep what they saved). The person shows separately. A new tx takes the debt's description when created; afterwards each keeps its own (sync = amount + date).
  - **Kind = category** (system categories, formal names, from the app's l10n by `system_kind` as `category_label.dart` does today; the chips stay colloquial: จดหนี้ | จ่ายหนี้). Not in reports.

    | Kind | Category (th) | Category (en) | `system_kind` |
    |---|---|---|---|
    | ให้ยืม | ให้กู้ยืม | Loan given | new |
    | ยืม | กู้ยืม | Loan taken | new |
    | จ่ายคืน | ชำระหนี้ | Debt repayment | `DEBT_PAID` |
    | รับคืน | รับชำระหนี้ | Debt collected | `DEBT_RECEIVED` |
  - System categories: the BE must also lock rename and "นับในรายงาน" (today only delete / move / children are locked; `categories/service.go` has an empty `if current.IsSystem {}`); the icon stays editable. The same rule for every system category (opening, adjust, transfer) — agreed.
- **Event:** each bill becomes case 2 (someone else paid, not paid back yet), 1 (paid back on the spot) or 3b (I paid); a lump = one "I owe X" debt connected to many "จ่ายโดย X" txs.

## Recurring debt per person — Agreed
- **A new recurring kind "หนี้"** (beside subscription, installment, income, reminder, saving), like "saving" was added: it has a person (as saving has a goal) and its slots are filled by person-book entries. The four directions are data inside the kind. "ผ่อน" (installment) stays for paying a shop / card (e.g. a phone at 0% for 10 months), which is an expense, not a debt with a person.
- A recurring rule tied to a **person**, not to one debt (a person's balance = all debts − all repayments).
- Same picker as the debt quick-create mode: chips **จดหนี้ | จ่ายหนี้** + the direction arrow, plus the schedule. All four are allowed (pay back, get paid back, lend, borrow); paying back is the common one.
- Confirming: จ่ายหนี้ → a repayment tx (occurrence ⇄ tx, rule 1); จดหนี้ → a debt row (+ its tx if ทำรายการเงิน is on).
- The end is set in the recurring rule as usual (count | date | none).
- จ่ายหนี้ rules:
  - the occurrence amount = the rule amount, or what is left if less (rule 500, left 200 → 200); recomputed until confirmed;
  - only **one** occurrence waits at a time: no new one until it is confirmed / skipped;
  - the balance reaches 0 → the system pauses the rule; a new debt (balance > 0) → it runs again, unless the user ended it;
  - a big payment (e.g. 2,000 in month 2) is just a confirm with an edited amount.
- Example: lent 200 (tx) + 300 (tx) + 2,000 ten years ago (note only) = 2,500; rule "รับคืน 500 / month"; month 1 → 2,000 left; month 2 they pay 2,000 → 0 → paused.

## 3 / 4. Event ⇄ my book — Agreed (revamp)
- An event is a shared book: bills = what was bought, who paid, who shares.
- **One model app-wide (owner 2026-10-26):** an event bill, a split bill and "someone paid for me" are the same pieces; only who paid differs. Example without an event: I buy A for 100, my partner pays because I forgot my money, I pay back next week → expense A 100 "จ่ายโดย แฟน" (wallet untouched) + debt "ฉันติดแฟน 100" (due date optional); next week a repayment tx 100 from my wallet → balance 0.

  | Who paid | My book | Name in the app |
  |---|---|---|
  | someone else paid for me | tx my share **"จ่ายโดย X"** + debt "ฉันติด X" (debt tx: connected + always synced) | คนจ่ายแทน (`paid_by`) |
  | someone else paid, I paid them back on the spot | tx my share from my wallet, no debt | — |
  | I paid, others share | tx whole bill from my wallet (reports count my share) + debts "X ติดฉัน" | แบ่ง |
  | I paid only my own | tx from my wallet, no debt | ส่วนตัว |

  - **"จ่ายโดย X" ≠ "ไม่ระบุกระเป๋า":** no wallet = the user doesn't track the wallet (no debt); "จ่ายโดย X" = the money came from X (a debt). The wallet slot shows "จ่ายโดย X".
  - A repayment tx is tied to the PERSON, not to a debt row: balance = debts − repayments; no closing of debts one by one.
  - The "จ่ายโดย X" tx is finished when saved: no "ยังไม่จ่าย" label, nothing to update later. What is still owed lives on the person ("เจ้าหนี้ X ฿…"); paying X later is a normal repayment tx.
  - **Quick create (แบ่ง / คนจ่ายแทน / อีเวนต์):** the wallet slot follows the payer. Payer = me → the wallet picker. Payer = X → "จ่ายโดย X" (grey, not pickable) + a tick "คืน X แล้ว" that brings the wallet picker back and makes no debt. The description is typed as usual.
- **Per bill** ("ลงบัญชีของฉัน" in the bill sheet): any time; each bill becomes one of the rows above, connected to the bill, synced per the auto-sync switch.
- **Lump** ("claim ก้อน" = recording a debt): any time, active or completed (owner 2026-10-26).
  - A lump = ONE debt "ฉันติด X" connected to many "จ่ายโดย X" txs (one per bill); its amount = their sum. A tx still connects to one debt only.
  - Based on the **real pairs** (not the simplified "fewest transfers" lines); bills already booked are left out.
  - The lump remembers which bills it covers. A bill in a lump can't be booked per bill again.
  - A bill in a lump is edited → its tx changes and the lump follows (auto sync on) or a notification asks (off).
  - A bill added after the claim → a new lump for the new bills.
- **Completed = locked for good** (owner 2026-10-26, replaces "completed still allows add / edit with a warning"):
  - only the **owner** can complete, after a confirm ("ปิดแล้วแก้ไม่ได้อีก และสมุดของทุกคนจะเลิก sync"); it can't be undone;
  - no more adding or editing bills; a mistake = a new event, or fix it in your own book;
  - every book is **unsynced** at once: the connected txs / debts become plain records of their owners, freely editable;
  - claiming is still allowed after completion, as a one-time copy (no sync).
- **Settle view:** while active, only the **real pairs** (the app today shows only the simplified lines; switch it to the BE `pairs`). **"จ่ายน้อยครั้งสุด" only after completion** (the pairs can't change any more):
  - each member taps "ลงในสมุดฉัน" on their own line → a one-time set in their book: a plain tx for the money that really moves + person-book entries without a tx that clear the real pairs; the two are NOT connected (different people).
  - Example: real pairs A owes B 300, B owes C 300; simplified: A pays C 300. A: tx "pay C 300" (wallet −300) + ชำระหนี้ B 300 (no tx). B: รับชำระหนี้ from A 300 + ชำระหนี้ C 300 (no tx, no money). C: tx "from A 300" (wallet +300) + รับชำระหนี้ from B 300 (no tx). Every book clear, every wallet right.
  - A member who doesn't tap it keeps the real pairs in their book and settles them as usual.
- Auto sync on → my tx / debt / lump follow the event; off → a notification asks; "no" = they stay different, still connected.
- **Who:** complete, archive, cancel and delete are owner-only.
- **Auto-sync switch:** a user-wide default in settings, overridable per event.
- **Claim and connect are the same link from two ends (owner 2026-10-26):**
  - claim = start in the event: pick a bill → make a debt / tx in my book;
  - connect = start in my book (the debt form or the tx form): pick an event → pick a bill, or create a new bill right away.
  - Any bill type can be picked; the amount comes from the bill (my amount with that person) and syncs per the auto-sync switch. A bill already claimed / connected can't be picked again.
  - A new bill from the debt form = a **debt-type bill**; from the tx form = an expense bill (today's quick-create event tab).
  - This is how paying back in my own book reaches the event (so the event can become settled).
  - One debt may connect to several bills (= a lump started from my book); the debt amount = their sum (agreed).
- **Debt-type bill** (agreed): money moving between two members ("A จ่าย B"), today's `payback` type widened: pay back, and lending during the event. Members can claim it into a debt or a tx like any bill, and it counts in the lump; the settle math already treats it as money from one member to another.
- **Deleting a bill:** auto sync on → my connected tx / debts are deleted too; off → a notification asks (delete them, or keep them disconnected).
- **System categories:** every system category (opening, adjust, transfer, the four debt ones) locks rename and "นับในรายงาน"; the icon stays editable.

### Today (survey 2026-10-26, from the code, not run)
- The event's numbers come only from event rows (expense bills + paybacks); personal debts / repayments never change them. The app shows only the simplified lines (greedy, can pair people who share no bill); BE `pairs` is unused.
- Event-level debt (`{event_id}`) = the simplified line amount at that moment, never recomputed; "recorded" = an exact amount match, so it can be recorded twice; per-bill debts are not subtracted → the person balance counts the money twice.
- Debts never follow a bill edit; tx follow only by a manual action.
- Bugs: "คืนแล้ว" when I paid books a repayment without the debt (I end up owing them); "คืนแล้ว" on me when someone else paid still books my debt; income bills are ignored by settle but booked like expenses; a share someone else paid can take a wallet AND a debt (counted twice); `_debtAlreadyBooked` uses my total balance with that person; editing a bill re-creates its split rows, so a copy pointing at a child row loses its FK and may hit `transactions_project_id_implies_source`; a payer who books the bill later from the sheet gets a "copy" (target = rest share) instead of the origin.
- `completed` today blocks new bills but allows edits (`projects/store.go` `writable`).
