## Proposed scope split
The whole concept is ~15 L-sized pieces. Proposal:
- **0.4.1-1 (this plan):** Base + Debts + Recurring (without the new "หนี้" kind) + the event bugs that break things today + the one BE "book bill" call + settle shows the real pairs.

Why: the events revamp and the "หนี้" kind both stand on the new person book (repayment rows, the 4 debt categories) built here; doing them in the same round means building on a moving base.

## Sync rules a–f (owner 2026-10-27)
- **a. Agreed:** unsync keeps the "came from" link (still connected); only the values stop following.
- **b. Agreed — shared bills (owner 2026-10-27):** an event bill and a split bill shared with linked contacts are the same thing: a **shared bill**. Every member holds their own copy, and every member opens the **same bill form** (total, payer, every share; my share marked).
  - Created from the normal quick create (add to an event / create a new one, or split with people); **once created, "edit" on that tx always opens the shared bill form** (event bill sheet / split bill form), whatever the auto-sync switch.
  - Anyone may edit: event bills by the event's rights, split bills by every member.
  - Saving a bill reaches each other member by **that member's** auto sync: on → their copy changes at once; off → a notification asks "อัปเดตตาม"; "no" leaves their copy "ไม่ตรง", still connected.
  - My copy when someone else paid: wallet slot shows "จ่ายโดย A", category and tags empty ("เลือกหมวด", "เลือก tag") for me to pick, and the debt "ฉันติด A ฿…" shows in my person book.
  - Event completed → "edit" opens the tx's own edit; it no longer syncs. Disconnect → a plain tx, edited freely.
- **c. Agreed:** "ไม่ตรง" + "อัปเดตตาม" shows only on a copy that is connected but not synced (auto sync off and the member said "no").
- **d. Agreed (owner 2026-10-27):** on a shared bill everything syncs except **category, wallet and tags** (each member's own). **Notes on shared records:** `note` = the shared note (synced); a new `private_note` = mine only, never synced; `private_note` exists only on shared records (event / split bills and their copies). Debt ⇄ my own tx (same owner): amount, date, description, note are one value. Only the system writes 0 amounts (sync, auto-create); a typed amount stays > 0, and a 0 row can be saved if its amount wasn't touched.
- **e. Agreed:** two separate auto-sync switches: events, and debts / split bills with a linked contact; each is the member's own (my book).
- **f. Agreed:** deleting my tx = disconnecting it (the bill / the other side is unchanged). Recurring keeps its own rule: deleting the tx skips the slot.
- **Write principle:** every write that touches a connected side is ONE BE call in ONE DB transaction, and the answer carries what changed elsewhere (`Effects{slots, debts, bills, person_balances, account_balances}`). Today several app flows chain 3–6 HTTP calls with no rollback (event bill sheet), so a failure halfway leaves half-booked rows.
- **Cross-user disconnect:** only the link between the two users breaks; the splitter's own tx ⇄ debt stays connected + synced.
- **Scope note:** the shared split bill (every member holds a copy and can edit; today it is a one-way debt mirror) goes to 0.4.1-2 with the rest of the shared-bill work (owner 2026-10-27).
